# 作業別 effort の選択

モデルを維持し、親エージェントが目的・影響・不確実性から実行前に選択する。パス・拡張子・差分量だけで自動分類しない。

## 選択基準（正本）

| effort | 条件 |
|---|---|
| low | 範囲が明確な事実抽出、定型作業、修正箇所だけの再確認 |
| medium | 通常のレビュー・実装・テスト設計・調査。判断材料不足の場合もここから開始 |
| high | 認証・課金・データ移行・並行処理、権限・実行制御・安全ゲートの変更、複雑な原因調査 |
| xhigh 以上 | high で解消できない論点、またはユーザーの明示指定 |

Markdown でも SKILL.md の権限・実行条件・安全ゲートを変える場合は high。昇格は未解決の論点に限定し、タイムアウト・認証失敗・使用量制限を理由に昇格・自動再実行しない。

## CLI 起動手順

1. ユーザーの明示指定、既存 effort 環境変数、Codex プロファイルを確認する。既存の明示値を維持し、自動判断で上書きしない。明示された空文字も未設定とは扱わず検証へ渡す。
2. 明示指定がなければ表から選び、値・理由を実行前に説明する。モデルは変更しない。
3. Claude は `MULTI_AGENT_CLAUDE_EFFORT`、Codex は `MULTI_AGENT_CODEX_REASONING_EFFORT` を、その呼び出しの環境へだけ設定する。Codex の `MULTI_AGENT_CODEX_PROFILE` が指定済みなら自動 effort を追加しない。profile と effort の両方が明示された場合は既存契約どおり effort が勝つ。
4. dry-run の要求値・出所を確認して同じ設定で実行する。異なる effort が必要なタスクは呼び出しを分ける。CLI に渡した要求値と、実使用値は区別する。

Claude の許可値は low / medium / high / xhigh / max。Codex は既存の許可値を使用する。モデル固有の対応は CLI が判定する。未対応や CLI 側の丸めを観測した場合はその事実を報告し、要求値どおりに適用されたと断定しない。

スクリプト直接利用では未指定のときフラグを渡さず CLI 設定へ委譲する。ログの「継承・実値未確認」は自動最適化や実設定確認の意味ではない。全セッションの共通設定は変更しない。

## ネイティブサブエージェント

委譲前に選択した effort・理由・指定手段を記録する。プロンプトに値を書くだけでは設定したことにならない。

- Claude: エージェント定義の `effort` または委譲元セッションの明示設定を使用する。第三者プラグインのキャッシュは編集・複製しない。定義側の上書きと実行表示を確認する。
- Codex: 利用可能な起動ツールの `reasoning_effort` を使用する。全履歴を継承する起動で個別上書きできない場合、独立した作業だけ必要情報を渡す新規コンテキストで起動する。履歴が必要なら継承を優先し、個別制御不可と記録する。
- ホストが指定を提供しない場合は継承・制御不可と記録する。実効値を確認できない経路を対応済みと報告しない。

## 比較試行

Claude/Codex それぞれで軽作業・通常レビュー・重要変更を固定入力で比較する。モデル・入力・観点をそろえ現行/提案を各1回、同一条件は重複実行しない。要求値、確認できた実設定、時間、取得可能なトークン量、有効指摘、見落とし、手戻りを記録する。未取得値は不明とし、トークン量を契約使用枠の削減率へ換算しない。

重大な見落としが増えた分類は採用せず従来設定を維持する。使用量を取得できない場合は削減効果未確認。少数試行を全案件へ一般化しない。
