# Skill references and GitHub routes

`bash verify.sh` retains the original relative-path scanner, including its fence
exclusion. A separate Python 3 pass includes paragraphs, tables and executable
fences that mention the `gh` command. It derives the current skill/reference set;
the Issue's named skills are required controls, not a fixed skill-count divisor.
Reference-only operations are discovered independently of the parent SKILL,
including nested references. Concrete relative Markdown links in audited
references are checked within the physical plugin boundary after relocation; fenced and parameterized examples
are excluded.

An operation block is followed by a hidden source signature and visible `MCP:`
guidance with concrete 取得値 / 形式 / 渡し先 / 不足時. The signature is a static
change canary, not a capability declaration or proof of equivalent behavior.
After editing an operation or its prose, review its alternative before updating
the signature. The checker reports unknown actions, generic substitutions,
missing dimensions, moved guidance, invalid classifications and orphan notes.
Three known copy/paste regressions additionally bind effort evidence, deploy
checks and protection probes to their actual consumer and failure policy.
Each of the three trigger operations must be found in its expected document;
format drift or a missing trigger fails even after a source signature refresh.
This narrow check does not establish general semantic equivalence.
CLI diagnostics, forbidden examples and nonoperative descriptions need local
reasons; they do not acquire an invented MCP implementation.

The self-test uses a small Markdown fixture and isolated Markdown-only copies of real docs in
`TMPDIR`. Every red checks file/operation/reason, and green variants check their
actual command/decoy remains present. Source and Git are read only; Python cache
writes are disabled. Missing Python, resources, target skills, unreadable docs,
zero matches and stub references fail. The merge contract additionally requires
the real six argument names within each canonical merge section.

This is a documentation consistency gate. It cannot establish connector
capabilities, complete live pagination, write success, host identity or runtime
equivalence. The documented raw contracts and actual write/read-back remain
separate verification requirements.
