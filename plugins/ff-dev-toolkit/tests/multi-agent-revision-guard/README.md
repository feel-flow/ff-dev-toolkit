# multi-agent-revision-guard

`multi-agent.sh` の実行中にレビュー対象（HEAD / ブランチ / 作業ツリー）が動いたとき、
誤った結果が「正常完走」として返らないことを固定する suite。

## 何を守っているか

対処は 2 つあり、**どちらか片方では穴が残る**。

| | 守るもの | 守れないもの |
|---|---|---|
| ② diff の固定 | 全タスクが同じバイト列の diff を読むこと | エージェントが作業ツリーのファイル実体を直接読む分 |
| ① 前後のリビジョン検証 | 実行中に対象が動いたら結果を破棄すること | 動いて**元へ戻った**変化（前後が一致する） |

②が無いと、並列タスクの起動時刻がばらける以上、実行中の `checkout` / `commit` で
タスクごとに別の瞬間の diff をレビューしうる。しかも全員が正常終了する。

## 構成

- **単体** — `capture_repo_snapshot` と `prompt_diff_content` を直接叩く。
  スナップショットの安定性・3 フィールド契約・E1/E1b/E2/E3/E6・内容成分
  （dirty ファイルの追加編集 / 既存 untracked の内容変更 / index だけの変化）・
  除外パス・**CWD 非依存**・detached HEAD・unborn・良性の symlink・glob メタ文字。
- **統合** — 一時 git リポジトリ + stub CLI で orchestrator を実走。正常系が
  誤発火しないこと（最重要の非回帰）、E1/E2/E3/E6 の検出、E4 の往復、`--staged`、
  出力先の境界検証、破棄時のマーキング、stale レポートの除去。
- **ミューテーション 5 件** — 検査が「たまたま通っている」だけでないことを、被検体を
  壊して確かめる。適用できたかは **`cmp -s`（被検体と同一なら失敗）** で判定する。
  パターン一致で判定すると、被検体の書き方が変わったときに変異が当たらないまま
  検査だけが通り抜ける。

| 変異 | 外すもの | 見逃されるはずのもの |
|---|---|---|
| M1 | 事後検証の呼び出し | 実行中の commit |
| M2 | 不在 `--diff-file` の fail-loud | 固定 diff の消失（従来取得へ戻る） |
| M3 | 指紋の `git diff HEAD` / `--cached` | 既に dirty なファイルの追加編集 |
| M4 | リポジトリ root への `cd` | 除外が CWD 相対に縮む（サブディレクトリ起動） |
| M5 | 指紋の `git diff --cached` | worktree を動かさない index だけの変化 |

## 注意

- **実 CLI は 1 つも起動しない**（stub で覆う）。ネットワーク・課金は伴わない。
- `--sequential` を使う検査がある。並列だと先行タスクの副作用が後続へ届く順序を
  作れず、中核シナリオ（タスク間で diff が食い違う形）を再現できない。
- `adapter-common.sh` を source した直後に **EXIT trap を張り直している**。
  source 時に無条件で trap が張られるため、張り直さないと一時ディレクトリが毎回残る。
