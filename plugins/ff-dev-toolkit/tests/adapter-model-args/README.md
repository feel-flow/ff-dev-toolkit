# adapter-model-args

アダプタが CLI へ実際に渡す argv を stub CLI で実測する。

## なぜこれをテストするか

`tests/no-hardcoded-model/` は「モデル slug が**書かれていない**こと」という負の主張を静的に見る。しかし静的検査では、次のような「設定したのに届かない」形の後退を捕まえられない:

- 環境変数名の打ち間違い（`MULTI_AGENT_MODEL_GEMINI_CLI` → `..._GEMENI_CLI`）
- フラグ名の取り違え（codex の `-m` を `--model` に変える）
- 組み立てた `MODEL_ARGS` を起動行で展開し忘れる
- `reset_model_args` を `add_model_arg` の後に置いて、組み立てた値を消す
- 値の語分割（`"model with spaces"` が 2 引数に割れる）

いずれも成果物からもログからも判別できない沈黙した後退なので、argv を実測して契約を固定する。**環境変数名はこの suite にリテラルで書いてある** — これが `skills/multi-review/SKILL.md` の表と実装の間の突き合わせになり、実装側だけ名前を変えると red になる。

実 CLI は起動しない。`PATH` の先頭に argv を記録するだけの stub を置くので、課金もネットワークアクセスも発生しない。

## argv の記録形式

stub は各引数を `<arg>` で囲んで記録する。

```
<exec><You are a code review agent...><--sandbox><read-only><-p><review>
```

空白区切りで連結すると、`"model with spaces"` が 2 引数に割れても記録が同じに見えてしまい、**語分割の退化を検出できない**（ACE-36-1 / `docs-template/08-knowledge/playbook/testing.md`）。区切り文字を入れるのはそのため。

## ケース表

| 群 | 検査 |
|---|---|
| 既定（env 未設定） | 全 4 CLI（claude / codex / gemini / copilot）がモデルフラグを渡さない |
| env 上書き | 4 CLI それぞれで、環境変数の値が期待するフラグに届く |
| ヘルパーの第 3 引数 | ベンダー中立な既定値が env 未設定時に渡り、env 指定がそれに勝つ（この経路を使うアダプタは無いので、ヘルパー単体で固定する） |
| 語分割 | 空白を含むモデル名が 1 引数に保たれる |
| codex プロファイル | 実在するプロファイルが `-p` に届く |
| codex プロファイル | ファイルが無ければ CLI を起動せず非 0 で落ちる |
| codex 排他 | `-m` と `-p` の同時指定を非 0 で拒否する |
| ヘルパー | `add_model_arg` が env 変数名でない第 2 引数を非 0 で拒否する |

## 設計上の判断

**codex のプロファイル不在をラッパーで落とす理由**: codex 0.144.5 は存在しないプロファイル名を**エラーにせず base config のまま完走する**（実測）。そのままだと名前を打ち間違えたとき「専用プロファイルでレビューさせたつもり」が成立し、成果物からもログからも判別できない。ACE-70-2 が記録した実害と同じ形なので、ラッパー側で事前に検証する。

**`-m` と `-p` を排他にする理由**: 併用すると `-m` のモデルがプロファイルのモデルに勝ち、reasoning effort だけプロファイル由来になる（実測）。「プロファイルで束ねたから不整合が起きない」という利点がちょうど失われる組み合わせなので、黙って通さない。

## 負例テスト（変異させたら赤くなるか）

| 変異 | 期待される結果 |
|---|---|
| アダプタの `add_model_arg` の env 変数名を 1 文字変える | 該当 CLI の「env が届く」ケースが red |
| codex の `-m` を `--model` に変える | 「`-m` に届く」ケースが red |
| 起動行から `${MODEL_ARGS[@]+"${MODEL_ARGS[@]}"}` を削除する | 該当 CLI の上書きケースが全部 red |
| `MODEL_ARGS+=` を `MODEL_ARGS=` （代入）に戻す | codex の `-m`/`-p` 併用時の片方が消える → ただし現在は排他チェックが先に落とすので、排他チェックを外した状態で露見する |
| 配列をやめて文字列連結 + 非クォート展開にする | 「空白を含むモデル名が 1 引数」が red |
| ヘルパーの第 3 引数を無視する実装に変える | 「env 未設定なら第 3 引数の既定値を渡す」が red |
| プロファイル存在検査を外す | 「ファイルが無ければ非 0」「CLI を起動しない」が red |
| `-m`/`-p` の排他チェックを外す | 「同時指定を非 0 で拒否」が red |

## skip 条件

次のいずれかで **suite 全体を** `○ skip` にする（部分 skip はしない）:

- perspective ファイルが見つからない
- git リポジトリ外（プロンプト構築が差分取得を伴うため）
- 一時ディレクトリを作成できない（read-only 環境）
