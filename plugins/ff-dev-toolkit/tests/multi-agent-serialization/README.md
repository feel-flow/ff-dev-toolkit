# multi-agent-serialization test

`scripts/multi-agent.sh` の free-tier 限定逐次化と、それ以外の tier でタスク並列を維持する契約を stub CLI で検証する suite。

## 並列維持の判定

standard tier の codex stub 2 本は、各自が開始マーカーを書いた後、相手のマーカーが現れるまで期限付きバリアで待つ。正しく並列なら両方がバリアを通過する。standard tier まで逐次化すると先行タスクは相手を起動できないため期限切れになる。短い滞留窓で交差を推測せず、10 秒までの spawn スキューを許容する。

検出力は、一時コピーした orchestrator の tier 条件へ standard tier を加える変異で実測する。変異が対象行へ 1 回だけ当たったこと、実行が非 0 になったこと、codex stub がバリア期限切れを記録したことをそれぞれ検査する。

free-tier の gemini stub は従来どおり 0.6 秒の滞留窓と start/end の厳密な交互列で逐次化を検査する。この既存検査は Issue #415 では変更しない。

## 実行時間

Issue #415 着手前の記録は約 27〜42 秒（外れ値 40.1 秒を含む）。期限付きバリア導入後、macOS の 10 logical CPU 環境で次を実測した（2026-08-12）。

| 条件 | 結果 | 所要時間 |
| --- | --- | --- |
| 通常負荷 | 19/19 pass | 18.35 秒 |
| 低優先度の CPU worker 20 本（logical CPU の 2 倍）を同時実行 | 19/19 pass | 20.12 秒 |

負荷時も codex 2 本はバリアを通過し、spawn スキュー由来の失敗は無かった。逐次化変異では先行 codex が 10 秒の期限切れとなり、suite が非 0 になることも同じ実行内で確認する。所要は着手前の実測範囲から大幅に増えていない。

件数や所要時間の記録を更新するときは、通常負荷と同等の高負荷条件を実測してから直す。
