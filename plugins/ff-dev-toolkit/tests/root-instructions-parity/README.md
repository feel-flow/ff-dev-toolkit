# root-instructions-parity

リポジトリ直下の指示文書（`HOST-PARITY.md` の routes 表 `root-instructions` が宣言する
届け先）の**記載一致**を機械検査する。現状の届け先は `AGENTS.md` と `CLAUDE.md` の 2 つ。

## 何を潰しているか

Claude Code は `CLAUDE.md` だけを自動で読み `AGENTS.md` を読まない（<https://code.claude.com/docs/en/memory>）。
Codex CLI / grok CLI は逆に `AGENTS.md` を読む。したがって開発ルールは**2 文書へ同じ内容で**
維持する契約になっている（ADR-056）。担保が「片方を更新したら、もう片方も同じ内容へ更新する」
という散文だけだと、片方にしか無い規定が黙って生まれる。

既存のゲートはこれを担保しない:

| ゲート | 見ているもの | 記載一致を担保しない理由 |
|---|---|---|
| `host-route-parity`（routes 表） | 届け先の**実在**（実体と宣言の集合一致） | ファイルがあることは、中身が届いていることではない |
| `host-route-parity`（contracts 表） | 表に載っている契約の検出語が各届け先に実在すること | 表に行の無い規定は対象外。表は「配ってあると宣言した契約」しか持たない |
| `docs-gates` の到達点検査 | `AGENTS.md` の参照行が正本パス + 節名 + 義務本文を満たすこと | 読むのは `AGENTS.md` だけ |

実測（2026-09-15）: 経路表が 2 届け先を宣言した状態で、**契約の検出語をどれも
含まない 3 行のスタブ `CLAUDE.md`** を置いても `host-route-parity` は全件 pass した。

## マーカーの書き方（ホスト固有の差の宣言）

2 文書には**正当な差**がある（自ホストの説明・インストールコマンド・repo-local スキルの
探索先）。これを比較から外すために、差のある箇所を文書側でマーカーとして宣言する。

```text
行単位:  <その行の末尾へ> <!-- host-specific:<ID> -->
区間:    <!-- host-specific:<ID>:start -->
         …（複数行）…
         <!-- host-specific:<ID>:end -->
```

- ID は英数字と `._-` のみ。**同じ ID を 2 文書とも持つ**（片方にしか無ければ赤）
- 区間は入れ子にしない。開きっぱなし・閉じ過多・形の違うマーカーは赤
- 行単位マーカーは行末に置く（箇条書きの途中へ区間マーカーの行を挟むとリストが切れるため、
  1 行だけの差はこちらを使う）
- マーカーが免除するのは**宣言した区間だけ**。区間の中身が 2 文書で同じなら赤にする
  （マーカーは「ここは違う」という宣言なので、同じなら宣言が腐っている）

正規化ルール（ホスト名の読み替え表など）で差を吸収する形は採らない。正規化は「正当な差分」と
「片方が腐った差分」を区別できず、検出器の側に例外が無限に増える。

## 検査項目

1. 対象ファイルを routes 表 `root-instructions` から導出する（この suite に名前を直書き
   しない）。届け先が 2 件未満なら exit 1
2. 各対象が**独立した通常ファイル**であること（symlink でない / 同一 inode でない）
3. 各文書のマーカー構造が解析可能で、ID が文書内で一意であること
4. マーカー ID の集合が 2 文書で一致すること（両方向）
5. 各マーカー区間の中身が 2 文書で**実際に異なる**こと
6. マーカー外の本文が**行単位で完全一致**すること。食い違うときは「最初に分かれる行」と
   「どちらにだけある行か」、およびマーカー外の行数の両方を出す
7. 比較対象が 0 行でないこと（全文をマーカーで免除すると検査が空振りするため）

件数は本文へ書かない（この suite 自身が並行リストの腐りを潰すためのもの）。

## この suite が見ないもの（原理的な限界）

- **マーカーで宣言した区間の中身は比較しない**。共有すべき規定を 2 文書ともマーカーで包んで
  から片方だけ書き換えれば通る。マーカーの濫用は人側 / レビュー側の受け持ちで、機械側は
  「区間の中身が実際に違うこと」までしか要求できない
- **意味の一致は見ない**。同じ行が両方にあることしか見ないので、規定が矛盾していても通る
- **マーカー外であっても、2 文書が同時に同じ方向へ腐った場合は検出しない**。両方から同じ
  規定を消せば一致したままになる（契約単位の実在は `host-route-parity` の contracts 表が見る）
- **文書の並び順の妥当性は見ない**。節の順序が 2 文書で同じであることは完全一致の副作用として
  担保されるが、その順序が読み手にとって適切かは判断しない

## 変異による検証

| 変異 | 期待 |
|---|---|
| 片方の文書にだけ規定を 1 行足す | 「マーカー外の本文が一致しません」+ `にだけある` 行で red |
| 共有行を片方から消す | 同上（消えた側が `にだけある` に出る） |
| 共有行の順序だけを入れ替える | 「最初に分かれる行」で red（集合比較だけだと落ちる差分） |
| ホスト固有区間（`install-entrypoint` など）の中身を片方だけ書き換える | **green のまま**（正当な差分を偽陽性にしない） |
| `CLAUDE.md` を `AGENTS.md` への symlink へ置き換える | 「symlink です」+「同一ファイルです」の **`✗` 2 行**で red |
| `CLAUDE.md` を `AGENTS.md` の verbatim コピーへ置き換える | 全マーカー区間の「中身が同じです」で red |
| 片方のマーカー ID を改名する（区間形・行単位形とも） | ID の集合不一致で red |
| 行単位マーカーのある行へマーカー形のコメントをもう 1 つ書き足す | **green のまま**（行末で一致したものをその行の宣言として採る） |
| 区間マーカーの `:end` を消す | 「区間 … が閉じられていません」で red |
| 既存マーカーを除いて 2 文書とも全文を 1 区間で包む | 「比較対象が 0 行です」で red |
| 既存マーカーを残したまま全文を 1 区間で包む | 「区間 … の中で区間 … が開かれています」で red（入れ子検出が先に出る） |

実測の結果は `verify.sh` ヘッダの「変異検出」節が正本（TESTING.md の
「新規検査を書いた直後の変異注入バッテリー」）。この suite は**恒久 selftest を持たない**
（TESTING.md §新設ゲートに恒久 selftest を要求しない）。

## 依存と適用範囲

外部ツールは要らない（`awk` のみ）。実 CLI を 1 つも起動せず、一時領域もネットワークも
使わない。マーカーの解析に渡す正規表現は ASCII だけで、本文（日本語を含む）は行単位の
文字列比較でしか扱わないのでロケールに依存しない。

リポジトリ内の依存は `tests/lib/host-parity-tables.sh`（`HOST-PARITY.md` の表リーダー。
`host-route-parity` と共有）を `.` で読み込む **hard dependency** で、不在なら冒頭で exit 1 する。

正本表もリポジトリ直下の指示文書も**開発元リポジトリにしか無い**。配布先 checkout
（repository 直下に `docs/` が無い）では行頭 `○ skip` + exit 0 で **suite 全体**をスキップする。
`run-all.sh` の必須名簿には載せず、`verify.sh` の `# run-all-required: no` 宣言で適用外である
ことを明示する。`docs/` があるのに正本表や対象文書が無い場合は「消された」であって適用外では
ないので、skip ではなく赤にする。

## 実行方法

```bash
bash plugins/ff-dev-toolkit/tests/root-instructions-parity/verify.sh
```
