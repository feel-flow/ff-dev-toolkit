# host-route-parity

ホスト経路パリティの機械検査。開発元リポジトリの `docs/06-reference/HOST-PARITY.md`
（ホスト間非対称の正本表）を読み、**規定が 1 ホスト経路だけに入っている状態**を検出する。

## 何を潰しているか

このリポジトリの成果物は Claude Code / Codex CLI / grok CLI のどれで動かしても同じ機能が
成立することを目的にしているが、**各ホストの入口は非対称**で、規定を 1 経路だけに書くと
他ホストでは存在しないのと同じになる。

| 経路 | 書き漏らすとどうなるか |
|---|---|
| ルート指示文書（`AGENTS.md` と `CLAUDE.md`） | Claude Code は `CLAUDE.md` しか自動で読まず、他 2 ホストは `AGENTS.md` を読むので、片方だけに書いた規定はもう片方のホストへ 1 行も届かない。逆にここで宣言していないホスト固有名の指示文書を新設すると、そのホストだけに届く規定を作れる |
| repo-local スキル入口（`.claude/skills` と `.agents/skills`） | 片側だけに置いたスキルは、もう一方のホストから**見えない**（Codex は `.claude/skills` を探索しない） |
| 配布スキル（`skills/*/SKILL.md`） | marketplace 経由の全ホストに届く正本。ここだけに書いた規定は、同梱ドキュメントの読者には届かない |
| 配布ドキュメント（`docs-template/05-operations/deployment/`） | 利用者と委譲先エージェントが読む正本節。ここから消えた契約は、委譲プロンプトへ常置されなくなる |

実測では、委譲の依存プリフライト契約を常置した回に「Codex 経路は worktree を作らない」という
非対称が実装後のレビューで初めて判明し、配置のやり直しになった（観測台帳 OBS-156）。

## 検査項目

1. 正本表の 4 ブロック（`hosts` / `routes` / `asymmetries` / `contracts`）の sentinel が
   **各1件・正順**であること（表を丸ごと消した変更を「0 行」で緑にしない）
2. `hosts` 表のホスト名の集合が、`scripts/multi-agent.sh` の `ALL_CLIS` と**一致**する（両方向）
3. `hosts` 表の対象外（`no`）行は理由が必須
4. `routes` 表の届け先がすべて**実在**し、対象ホストがすべて `hosts` 表の対象であること
5. 対象ホストはいずれも**最低 1 経路から届く**こと
6. `routes` の `root-instructions` が、リポジトリ直下に実在するホスト指示文書と**一致**する（両方向）。
   候補名簿はファイル形とディレクトリ形の両方を持ち（Cursor の現行 Project Rules は `.cursor/rules/`、
   `.cursorrules` は後方互換）、実在判定は `-e` で行う
7. repo-local スキルの集合が正本側と Codex 入口で**一致**し、Codex 入口が正本への相対 symlink で、
   同一の `SKILL.md` を指すこと。**壊れた symlink も列挙に残す**（`-e` はリンク先を追うので、
   `-L` を or で足さないと宙に浮いた入口が集合照合からも symlink 検査からも消えて緑になる）
8. 入口検査スクリプトが参照する名簿が、正本側のスキル集合と**一致**する。スクリプトの path は
   `asymmetries` 表 `skills-discovery` 行の一次情報から引く（`*.sh` がちょうど 1 件）。
   **見つからない場合は skip ではなく赤**（開発元で改名・移動されたシグナルであって適用外ではない）
9. `asymmetries` 表のホスト列が対象ホストと**一致**し、各行の一次情報パスが実在し、
   「判明した経緯」に Issue / PR / ADR / OBS のいずれかの番号があること
10. `asymmetries` 表のホスト列に空欄も `-` / `TODO` のようなプレースホルダも無いこと
    （どちらも「非対称が無い」と読まれる。表自身が「未実測は明記する」を運用ルールにしている）
11. `contracts` 表の各契約について、宣言した**すべての経路**で、その経路の**正本ファイル**に
    検出語が実在すること（経路配下の hit を合算しない。下の「正本ファイル列の設計」を参照）
12. 各表が 1 行以上あり、照合が 1 件以上走っていること（検査の空振り検出）

件数は本文に書かない。**この suite 自身が count-rot を防ぐためのもの**なので、ここに
「N 件の経路」のような数を直書きすると真っ先に腐る（`cli-registry-completeness` と同じ方針）。

### 正本ファイル列の設計

`contracts` 表は「到達すべき経路」に対して、**その経路の届け先 1 つにつき 1 ファイル**の
「正本ファイル」を持つ。検出語の実在はそのファイルに対してだけ要求する。件数（宣言した全
経路の届け先の総数）が食い違えば、どの届け先にどのファイルが対応するか決まらないので照合
せずに赤にする。どの届け先の配下にも無い正本ファイルも赤にする（経路と正本ファイルの対応が
ずれた編集をそこで止める）。

届け先とファイルの対応づけは**並び順ではなく配下関係**で決める。届け先が 2 つある経路と
そうでない経路が混ざった行では、並び順だと「何番目がどの届け先か」が読み手にも機械にも
決まらない。表を読みやすくするために経路・届け先と同じ並びで書く運用にしているが、それは
**慣習であって機械検査の要求ではない**。同じファイルが 2 つの届け先へ対応づいた場合
（届け先が入れ子のとき）は、余った側が「対応づかない」形でしか現れず原因が読めないので
名指しで赤にする。

1 経路 1 ファイルで固定していた頃は、`root-instructions` のように届け先が 2 つある経路で
**片方に書いてあれば緑**になった。2026-09-15 の実測では、5 契約の検出語をどれも含まない
スタブ `CLAUDE.md` を置いた状態で全 33 件 pass している。2 文書の**記載一致**そのものは
`root-instructions-parity` suite が別に見る（契約表に行の無い規定はあちらが受ける）。

経路配下の hit を合算しない理由: 合算すると**正本節を消しても、同じ経路の別ファイルに残った
参照文で緑になる**。実測でも `deployment-docs` 経路の正本節は 1 ファイルの見出しだが、同じ経路の
別ファイルに同じ語を含む参照文があり、見出し側だけを消しても検出されなかった。

逆に「経路配下の全ファイルに検出語を要求する」形にはしない。`deployment-docs` のように
1 経路が多数のファイルを持つ届け先では、書く必要の無いファイルまで赤にしてしまう。

## この suite が見ないもの（原理的な限界）

- **新しい規定を 1 経路だけに書いた場合は赤にならない**。`contracts` 表に行が無いためで、
  行を足すのは人側の受け持ちである。本 suite が見るのは「配ってあると宣言した契約が、
  その経路から消えていないか」だけ。正本表 §5 の手順 3 がこの残余を受ける
- **検出語の一致は、規定の内容が同じであることを意味しない**。節見出しが残ったまま本文が
  空になれば通る。文言そのものの凍結が要る契約は `review-freeze-contract` 系の節スコープ照合を使う
- **ホストの実挙動は測らない**。「grok で plugin hooks が発火しない」等は実機検証の記録であって、
  この suite が再実測するものではない（再実測には課金セッションが要る）
- **`ROOT_INSTRUCTION_CANDIDATES`（既知のホスト指示文書名）は手で維持する allowlist**。
  ここに無い名前の指示文書を新設すると検出されない。新しいホストを開発に使い始めたら足すこと
- **入口検査スクリプトの名簿照合は、スクリプト全文からパス形の文字列を拾って導出している**。
  検査分岐で実際に使われているかまでは見ないので、コメントや `echo` の中にパスを書くだけでも
  一致してしまう。構造化した名簿から引く形にするには `scripts/check-repo-skill-entrypoints.sh`
  側を名簿駆動へ変える必要があり、そちらは本 suite のスコープ外
- **正本ファイル内での位置は見ない**。検出語が正本節の見出しにあるのか、同じファイルの別の
  段落にある参照文なのかは区別しない（節スコープの照合が要る契約は `review-freeze-contract`
  系を使う）

## 変異による検証

needle を足したら、対応する変異を手で当てて red を確認すること（緑は検査が効いている証拠にならない）。
下表は初版とレビュー対応の両方で実測済み。

| 変異 | 期待 |
|---|---|
| ルート指示文書から契約の検出語を落とす | 「`root-instructions` から消えています」で red |
| 正本側にだけ repo-local スキルを足す（Codex 入口なし） | 集合不一致 + 入口検査名簿の不一致で red |
| Codex 入口にだけ symlink を足す（正本なし） | 集合不一致 + 向き先不正で red |
| Codex 入口を symlink から実体コピーへ変える | 「symlink ではありません」で red |
| リポジトリ直下へホスト固有名の指示文書を新設する | `root-instructions` の集合不一致で red |
| `routes` が届け先として宣言している直下の指示文書を削除する | 「実在しない届け先を指しています」+ `root-instructions` の集合不一致（`routes 表 にだけある:`）の **`✗` 2 行**で red |
| `hosts` 表から 1 行落とす | `ALL_CLIS` との集合不一致で red |
| 非対称行の「判明した経緯」から番号を消す | 「番号がありません」で red |
| 非対称行の一次情報を実在しないパスへ差し替える | 「実在しない一次情報」で red |
| `routes` の届け先を実在しないパスへ差し替える | 「実在しない届け先」+ その経路の全契約が到達しないで red |
| `contracts` の経路宣言を `routes` に無い名前へ | 「routes 表に無い経路」で red |
| sentinel を 1 つ消す | 「sentinel が一意・正順ではありません」で exit 1 |
| `docs/` があるのに正本表を消す | 「正本表が見つかりません」で exit 1（skip ではない） |
| `contracts` の正本ファイルから検出語だけを落とす（同じ経路の別ファイルには残す） | 「正本ファイル … にありません」で red |
| `contracts` の正本ファイルを、宣言した経路のどの届け先配下でもないパスへ差し替える | 抜けた届け先の「正本ファイルがありません」+ 差し替えたファイルの「宣言した経路の届け先配下にありません」の **`✗` 2 行**で red |
| `contracts` の正本ファイルから 2 届け先のうち片方（`CLAUDE.md`）を落とす | 「届け先と正本ファイルの件数が違います」で red |
| 2 届け先のうち片方（`CLAUDE.md`）からだけ契約の検出語を落とす | 「`root-instructions` の届け先 `CLAUDE.md` から消えています」で red（`root-instructions-parity` は host-specific 区間内の差を見ないので green のまま = この赤は本 suite 固有） |
| `contracts` の正本ファイルへ同じ届け先のファイルを 2 件書く（もう片方の届け先を潰す） | 「届け先 … 配下に正本ファイルが 2 件あります」+ 潰した届け先の「正本ファイルがありません」の **`✗` 2 行**で red。配下にあるファイルを「配下にありません」とは報告しない |
| Codex 入口の symlink の向き先を実在しないパスへ（壊れた symlink にする） | 「正本と同一の `SKILL.md` を参照していません」で red |
| 入口検査スクリプトを改名し、`asymmetries` 表の一次情報はそのままにする | 「入口検査スクリプトが実在しません」+ 一次情報の不在で red（skip しない） |
| `asymmetries` のホスト列を `-` へ置換する | 「プレースホルダです」で red |

初版はこの変異実測で**自分のバグを 1 件拾っている**: 契約が 1 経路から消える変異に対し、
`x="$(grep ... | awk ...)"` の裸代入が `set -euo pipefail` のもとで grep の rc=1 ごと
代入を失敗させ、**✗ 行もサマリーも出ないまま rc=1 で死んでいた**（赤いが理由が読めない形）。
現在は `count_matching_files` が rc 0 / 1 を受理し、2 以上だけを名指しの失敗として上げる。

この suite は**恒久 selftest を持たない**（TESTING.md §新設ゲートは恒久 selftest を要求しない）。
検査に手を入れたら上表の変異を手で 1 回撃ち、`✗` 行と rc を PR 本文へ貼ること。

## 依存と適用範囲

外部ツールは要らない（`awk` / `grep` / `sed` / `readlink` のみ）。実 CLI は 1 つも起動せず、
一時領域もネットワークも使わない。マルチバイト文字列は `grep -F`（固定文字列）としてしか
扱わないので、正規表現のロケール依存を持たない。

リポジトリ内の依存は 2 つとも `.` で読み込む **hard dependency** で、不在なら冒頭で exit 1 する。

- `tests/lib/cli-registry-parser.sh`: `hosts` 表と `ALL_CLIS` の集合一致に使う CLI レジストリの
  静的パーサ。`cli-registry-completeness` / `adapter-sandbox-contract` も使う
- `tests/lib/host-parity-tables.sh`: `HOST-PARITY.md` の 4 表のリーダー（sentinel の切り出し・
  行と列の分解・経路 ID からの引き当て）。`root-instructions-parity` と共有する。表形式を知って
  いるコードを 2 箇所へ写さないためのもので、写すと「同じ表を読んでいるはずの 2 つの検査が
  別のものを読む」形でドリフトする

正本表・repo-local スキル入口・入口検査スクリプトはいずれも**開発元リポジトリにしか無い**。
配布先 checkout（repository 直下に `docs/` が無い）では行頭 `○ skip` + exit 0 で
**suite 全体**をスキップする（部分 skip はしない）。`run-all.sh` の必須名簿には載せず、
verify.sh の `# run-all-required: no` 宣言で適用外であることを明示する。

`docs/` はあるのに正本表や入口検査スクリプトが無い場合は「消された・改名された」であって
適用外ではないので、skip ではなく赤にする（部分 skip の経路を 1 つも持たない）。

## 実行方法

```bash
bash plugins/ff-dev-toolkit/tests/host-route-parity/verify.sh
```
