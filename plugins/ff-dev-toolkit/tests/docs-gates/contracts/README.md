# docs-gates の契約データ

「規定の所在が消えたら赤にする」宣言的な検査を、**契約ごとに 1 ファイル**で置く場所です。
`verify.sh` はこのディレクトリを glob して全件を実行します。

## なぜファイルを分けるのか

契約が増えるたびに `verify.sh` の末尾へ needle を足す運用だと、**別々の規定を固定する
PR どうしが同じファイルの同じ領域を触る**ため、並行作業のたびに競合解決が要ります。
実測では 2 つの PR が同じファイルへ needle を追加し、書き手が「末尾へ追加する」と
意識して回避していました。回避は書き手の注意に依存していて、構造は守っていません。

契約ごとにファイルを分ければ、新しい規定を固定する PR は**新しいファイルを 1 つ足すだけ**で、
既存ファイルを 1 行も触りません。別の規定を足す PR とは異なるファイルなので競合しません。

## 書式（タブ区切り）

1 行 1 検査。`#` で始まる行と空行は無視されます。

| 種別 | 欄 |
| --- | --- |
| `contains` | `contains<TAB>相対パス<TAB>固定文字列<TAB>ラベル` |
| `section` | `section<TAB>相対パス<TAB>見出し<TAB>固定文字列<TAB>ラベル` |
| `matches` | `matches<TAB>相対パス<TAB>拡張正規表現<TAB>ラベル` |
| `absent` | `absent<TAB>相対パス<TAB>固定文字列<TAB>ラベル` |

- 相対パスは `docs-template/` 起点（`verify.sh` の `DOCS` と同じ基準）
- `section` は見出し行の**リテラル前方一致**で節を切り出してから照合します（節の外へ
  写した文言で合格しないため。実装の正本は `tests/lib/section-scope.sh`）
- 固定文字列にタブと改行は書けません。必要なら `matches` を使うか、`verify.sh` 側へ
  手続き的な検査として書いてください

## ファイルを足す / 消すときは `MANIFEST` も直す

`MANIFEST` はこのディレクトリに在るべき `.tsv` の一覧です。`verify.sh` が実体と
突き合わせ、食い違えば赤にします。

ファイルごと消えた契約は、**残ったファイルが 1 行でも返す限り件数側の検査に掛かりません**
（「1 ファイルも無い」「1 行も読めない」は赤ですが、2 ファイル中 1 ファイルが消えても
残りが緑を出します）。消えたことに気付ける知識は、消えたファイルの外にしか置けないので、
一覧をここに持ちます。

同じ理由で、`verify.sh` はこのディレクトリの中身も検分します。`README.md` / `MANIFEST` /
`*.tsv` 以外の要素、symlink、名前に制御文字を含む要素があれば赤です。それぞれ塞いでいる穴:

| 要素 | 塞がないとどうなるか |
| --- | --- |
| `.tsv.bak` などへの改名 | glob から外れて「対象が無い」と読まれ、静かに素通りする |
| 隠し名（`.` 始まり）への退避 | `*` の展開に載らないので、走査したつもりの検分から漏れる |
| symlink | 実体をディレクトリ外へ逃がせる（中身が差分に出ないまま変わる） |
| 名前に改行を含むファイル | 一覧との突合が「1 ファイルを 2 行」と数え、実在しない契約を在ることにできる |

一覧を `verify.sh` ではなくここへ置くのは、**契約を足す PR が `verify.sh` を触らずに済む**
というこのディレクトリの目的を保つためです。

### 検出できないこと（設計上の下限）

契約ファイルの中身を**別の通る行へ置き換える**変更は緑のまま通ります。行数・欄の形・
ファイルの実在はすべて満たすためです。`MANIFEST` に契約ごとの必須行数を持たせれば
行数の変わる置換だけは拾えますが、行を 1 本足すたびに共有ファイルを編集することになり、
このディレクトリが消そうとしている競合面が戻ります。

ここは機械ではなく運用側の規律が担います — **契約行を足したら、規定側を落として一度
赤にすることを確かめてください**（リポジトリ正本 `docs/04-quality/TESTING.md` の
変異注入バッテリー）。`verify.sh` の needle ブロックを書き換える変更が同じように
検出できないのと同型で、いずれも差分には現れます。

## どちらへ書くか

- **宣言的に書ける**（対象文書・節・固定文字列・ラベルだけで表せる）→ ここ
- **手続きが要る**（複数ファイルの突き合わせ、抽出したパスの実測、条件分岐）→ `verify.sh`

ここへ置いた検査も `verify.sh` の検査も、同じ `ok` / `bad` に集計されます。
