# /ace-refine — 操作別の適用手順（R3-a〜R3-d）

R2 で承認された操作の種類の節だけを読む（archive だけなら R3-a だけ）。どの節も、本線 `SKILL.md` の **R3-0**（archive へ追記する前に対象 ID の既存出現数を数え、0 / 1 / 2 件以上で分岐する）を先に通す前提で書いてある。適用後は本線の R3-e へ戻る。

## R3-a. stale エントリのアーカイブ

1. アーカイブ先 `docs/08-knowledge/playbook/archive/<category>.md` が無ければ新規作成する:

   ```markdown
   # PLAYBOOK Archive — <カテゴリの日本語ラベル> (<category>)

   > **Parent**: [PLAYBOOK.md](../../PLAYBOOK.md) — アーカイブ済みエントリの保管場所。
   > `playbook/archive/` 配下は `ace_entry_count`・カテゴリ件数ゲート・reuse 集計の対象外。
   > 参照リンクが切れていた場合はこのディレクトリを ID で grep して探す。
   >
   > **保全本文内の相対リンクは live 基準**: 各エントリ本文は原文を verbatim 保全しているため、本文中の `./<category>.md#ace-xxx` は `playbook/` 直下を指す live 側のリンクである。このディレクトリから辿ると (a) ファイルが存在しない、(b) anchor が無い、(c) **live ではなくアーカイブ済みの複製に着地する**（リンクチェッカーには映らない）のいずれかになる。本文内リンクを辿るときは `../<category>.md#ace-xxx` に読み替えるか、[PLAYBOOK.md の索引テーブル](../../PLAYBOOK.md#エントリ一覧) から live を引くこと。

   ---
   ```

   docs 規約で frontmatter が必須なら見出しの**上**に置いてよい（注記は Parent ブロック内のまま。`check-archive-links` は先頭の frontmatter を読み飛ばす）。**保全本文内の相対リンクは書き換えない**（書き換えれば verbatim 保全が壊れる）。代わりにこの冒頭注記が必須で、`./` リンクを 1 件でも含むファイルでは省略できない（機械ゲートが強制する）。

2. **R3-0 の分岐に従う**。未保全（0 件）ならブロック全体（anchor 行〜終端 `---`）を **verbatim で**アーカイブファイル末尾へコピーし、見出し直後に理由ヘッダを挿入する:

   ```markdown
   > Archived: YYYY-MM-DD / 理由: helpful=0・<N>日以上参照なし（/ace-refine）
   ```

   保全済み（1 件）なら**原文を再コピーせず**、既存ブロックの provenance 行へ同じ `> Archived:` 行だけを追記し、理由欄に保全の出所を添える（例: `原文は 2026-07-31 の圧縮で保全済み`）。過去に圧縮したエントリはすべてこちらに当たる。

3. **アーカイブ書き込みの検証（必須）**: 当該 ID の見出しがアーカイブ先に**ちょうど 1 件**あることを確認してから live 側を削除する:

   ```bash
   [ "$(grep -c "^### <ID>:" docs/08-knowledge/playbook/archive/<category>.md)" -eq 1 ]
   ```

   0 件（書き込み失敗）でも 2 件以上（重複）でも live 側に触れず中断する。存在だけを見る形（`grep -q`）へ戻さない。

4. live 側（`playbook/<category>.md`）から当該ブロックを、`PLAYBOOK.md` の索引テーブルから当該行を削除する。
5. `docs/` 配下をアーカイブした ID で grep し、`playbook/<category>.md#ace-x` 形式のリンクを `playbook/archive/<category>.md#ace-x` へ書き換える。書き換えるのは「archive されたエントリを指すリンク」だけで、「archive された本文の中のリンク」は触らない。過去の統合先をアーカイブするときは、archive 側にある統合元の `> Merged into:` も `../<category>.md#ace-x` → `<category>.md#ace-x`（同一ファイルなら `#ace-x`）へ付け替える。**`./` は付けない** — `check-archive-links` が live 基準リンクとして数え、冒頭注記の主張と食い違う。この張り替えが R3-b 第 2 変種（本文は逐語同一）で保全したエントリの本文に及ぶと、その provenance が偽になりうる。
6. 既存のアーカイブファイルへ追記した場合は、冒頭に手順 1 の注記があるか確認し、無ければ追加する。

## R3-b. 長大エントリの圧縮

1. **先に**原文ブロックをアーカイブへ保全し、見出し直後に理由ヘッダを挿入する。変種は「live 側の本文文字列が原文と逐語同一かどうか」で選ぶ（1 文字でも変えたら (a)、メタ表の再整形だけなら (b)）:

   ```markdown
   > Compacted: YYYY-MM-DD（live 側を要約済み。本文の原文は本エントリが正）
   ```

   ```markdown
   > Compacted: YYYY-MM-DD（live 側はメタ表のみ正準フォーマットへ再整形。本文は逐語同一で無改変。本エントリが原文）
   ```

   (b) のときに (a) を使うと「要約済み」が虚偽になる（archive は監査記録）。要約とメタ表の再整形を両方したら (a)。接頭辞 `Compacted:` は両変種で共通にする（archive を `Compacted:` で grep する運用があり、別接頭辞を作ると圧縮履歴が 2 系統に分裂する）。

2. **アーカイブ書き込みの検証（必須）**: R3-0 の分岐と一意性検証に従う（保全済みなら原文を再コピーせず、既存ブロックへ今回の `> Compacted:` 行だけを追記する）。アーカイブ先の当該 ID が**ちょうど 1 件**であることを確認してから live 側を書き換える。
3. live 側を [PLAYBOOK.md のエントリテンプレート](../../../docs-template/08-knowledge/PLAYBOOK.md#エントリテンプレート)へ意味保存で要約する（不変フィールドと 30 行例外は同テンプレートと「[行数バジェット例外の有効条件](../../../docs-template/08-knowledge/PLAYBOOK.md#行数バジェット例外の有効条件)」が正本）。

## R3-c. 近似重複の統合

抽象度統合（ADR-047）も同じ手順を通す。違いは手順 7 だけである。

1. 残す側 = 総参照数（git 参照 + 相互参照）の多い方。同数なら**古い ID** を残す。
2. 残す側の `Helpful` / `Harmful` に統合される側の値を**合算**する。
3. 統合される側をアーカイブへ verbatim でコピーし、見出し直後にポインタを挿入して、**archive 側のコピーの `Status` を `merged` に変える**（verbatim 保全の唯一の例外。変えるのは `Status` 行だけで、統合先の Status は触らない）:

   ```markdown
   > Merged into: [ACE-YYY](../<category>.md#ace-yyy)（YYYY-MM-DD /ace-refine）
   ```

   **保全済み（R3-0 で 1 件）なら原文を再コピーしない**。既存の archive レコードへ `> Merged into:` を追記して `Status` を `merged` に変える。

4. **アーカイブ書き込みの検証（必須）**: 統合される側の ID が**ちょうど 1 件**（`grep -c "^### <ID>:"`）であることを確認してから、live 側から当該ブロックを削除する。0 件でも 2 件以上でも live 側に触れず中断する。
5. `docs/` 配下の統合された側へのリンクを残す側へ書き換え、索引テーブルから統合された側の行を削除する。
6. 吸収した観点が残す側に欠けるなら 1 文だけ追記してよい（意味保存の範囲内）。
7. **抽象度統合のとき（残す側の本文を書き換えるとき）だけ**、次の順で行う。残す側の原文は手順 3 では archive へ運ばれないので、書き換える前に保全する:
   1. 残す側を R3-b の **(a) 第 1 変種**で保全する（R3-0 の分岐に従う）
   2. 残す側 ID がアーカイブ先に**ちょうど 1 件**であることを確認する（0 件でも 2 件以上でも中断）
   3. live 側のタイトル・適用条件を上位主張へ書き換える（固有名は例示として残す）
   4. 上げた主張から元エントリそれぞれのアクションが再導出できるか確認する。できなければ統合を取り消して両方を live に残す（ADR-047 決定 3）
   5. 索引テーブルの残す側の行のタイトルも更新する。索引と本文見出しの一致を検査する機械ゲートは無いので、`grep -n "^| *<ID> " docs/08-knowledge/PLAYBOOK.md` と見出しを目視で突き合わせる。**索引行は列幅にパディングされている**ため `"^| <ID> |"` の形は 1 件もヒットしない（ID の直後は空白 1 つ以上を許す）
   6. R3-e の Changelog に `- Merged: …` に加えて残す側の ID を `- Compacted:` へ記録する（`check-refine-invariants` が 1. の保全と対で検証する）

## R3-d. PATTERNS.md への昇格（蒸留オーバーレイ）

domain はこの操作の対象外（[domain.md](domain.md) の別 PR 経路を使う）。

1. 昇格先 `docs/03-implementation/PATTERNS.md` の節を「実証済みパターン（ACE 昇格）」の**部分一致**で探す（節番号は文書ごとに違うので完全一致で探して重複節を作らない）。節が無ければ節ごと追加し、初回はプレースホルダ行 `- 該当なし（昇格発生後に追記）` を削除する:

   ```markdown
   ### [パターンを一言で表す見出し]

   [ルール本文 1〜3 行。実装前に読んで即適用できる命令形で書く]

   出典: [ACE-XXX](../08-knowledge/playbook/<category>.md#ace-xxx)
   ```

2. 昇格は**移動ではない**。元エントリは live に `Status: active` のまま残す。収載済みの ID はスキップする（冪等）。非 active エントリは昇格させない。
3. PATTERNS.md の Frontmatter（`version` minor +1・`updated`・`changeImpact: medium`）と、`## Changelog` があればその版のエントリも更新する。
