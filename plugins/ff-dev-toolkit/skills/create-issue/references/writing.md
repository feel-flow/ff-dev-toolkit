# Issue のタイトルと本文の書き方

`/create-issue` が手順 3 でタイトルを、手順 6 で本文を書くときに読む（毎回）。`/out-of-scope-issue` と `/retrospective` が新規に起票するときも、この規定に従う。狙いは、読み手が一覧のタイトルと本文の冒頭だけで「何のための Issue で、何が良くなるのか」を掴めるようにすること。経路ごとの雛形（`/create-issue` の SKILL.md 手順 6、`/out-of-scope-issue` の references/filing.md §3.3）は各スキルが持ち、節の中身と順序はここが正本になる。

## タイトル

形式は `<type>: <何が・誰が> <どう良くなるか>`。bug は「何が起きているか」を書く。

- **結果か効果を書く。** 仕組みの名前（関数名・変数名・設定キー・オプション名）は本文へ回す。利用者が打つコマンド名（`/create-issue` など）は残してよい
- **管理情報はタイトルに入れない。** 台帳の番号（OBS / ACE / ADR）、Count、導入先の名前、「再発」「regression」といった経緯は、本文の `## 関連` へ書く
- **長さは 40 文字前後を目安にする。** 1 つのタイトルに書く変更は 1 つまでにする。「〜し、〜する」で変更を 2 つつないだら、片方は本文へ移す（変更とその効果を「〜し、〜する」でつなぐのはよい）
- `<type>` は conventional-commit の接頭辞（例: `feat` / `fix` / `refactor` / `chore` / `docs` / `test`。プロジェクトの分類に合わせる）で、type ラベルと食い違わせない。汎用タスクは `【タスク】` 形式にしてよい。`--bundle` の `bundle:` 接頭辞は今までどおり付ける
- スクリプトが決まった形で付けるタイトル（リリース作業のスクリプトが作る Issue など）は、この規定の対象外

書き換えの例:

| 書き換え前 | 書き換え後 |
| ---------- | ---------- |
| fix: load_settings が空文字の環境変数を None に変換せず、parse_port で KeyError を投げる（OBS-xxx 再発・Count 3） | fix: 環境変数が空のとき、設定の読み込みが KeyError で止まる |
| feat: 一覧 API に cursor パラメータを足し、OFFSET の代わりに keyset ページングで次のページを返す | feat: 件数が多い一覧でも、次のページをすぐ表示できるようにする |
| docs: README の準備手順の npm install を pnpm install --frozen-lockfile へ置き換え、Node 20 前提を書く | docs: 開発環境の準備手順を、今の手順に合わせて直す |

## 本文の節と順序

次の順に `## ` 節を並べる。先頭の 3 節で「なぜ・何のため・どんな効果か」が分かるようにし、仕組みの細部や管理番号は後ろの節へ回す。

| 節 | 書くこと | 7W2H1G |
| -- | -------- | ------ |
| `## ユーザーストーリー` か `## ジョブストーリー` | 1 文で、誰が（どんな場面で）何をしたくて、何を得るか。feature / docs はユーザーストーリー、それ以外はジョブストーリー | Whom・What・Why |
| `## 背景` | なぜ必要か。今どう困っているか、どの場面で起きたかを 1〜5 行で書く。bug は再現手順・期待する動作・実際の動作もここに書く。台帳の番号や詳しい経緯は `## 関連` へ回す | Why・When・Where |
| `## 目的と期待効果` | 目的（何のためにやるか）、効果（何がどれだけ良くなるか。数字か、目で確かめられる変化で書く）、得をする人 | Goal・How much・Whom |
| `## やること` | 対象（プラグイン・スキル・ファイル）と方針（1〜3 行）。代替案（選ばなかった理由も）とやらないことは、あるときだけ書く | What・Where・How・Which |
| `## 参照文書` | 着手前に読む文書（`/create-issue` の手順 2） | — |
| `## 受け入れ条件（AC）` | Given-When-Then と Definition of Done（`/create-issue` の手順 4） | — |
| `## 関連` | 関連する Issue・PR、台帳の番号、関連 ACE エントリ、詳しい経緯。タイトルから外した管理情報もここへ書く | — |
| `## 工数見積もり（KPI 計測）` | 工数ブロック（`/create-issue` の手順 3・6） | How much |

細かい実装手順は Issue に書かず、PR に書く（Issue に書いた手順は、着手時の実測で外れて古くなる）。

## 書く前の点検（7W2H1G）

7W2H1G（When・Where・Who・Whom・What・Why・Which・How・How much・Goal）は見出しにしない。書き終えた本文を、上の表の右列で点検するのに使う。

- **必ず埋める:** Why（背景）、Goal と How much（目的と期待効果）、What（やること）
- **1 行で足りる:** Whom（得をする人）、Where（対象）
- **あるときだけ書く:** When（起きる場面。背景の中に書く）、Which（代替案）、How（方針。細部は PR へ）
- **書かない:** Who（誰がやるか。assignee で足りる）、期限（priority ラベルで表す）

本書の節に無い項目のために、節や「なし」だけの行を足さない。効果の数字は、実測か根拠を示せる見込みだけを書き、推測で作らない（数字が無ければ、目で確かめられる変化で書く）。

確認を挟まずに起票する経路（`/create-issue` の手順 1「非対話モード」、`/retrospective` の自動起票）でも、目的と期待効果・やることは、依頼の文・ストーリー・背景・提案から書ける範囲で書く。書けないことを推測で補わない。受け入れ条件とストーリーの扱いは、各経路の規定（`/create-issue` は手順 1、`/retrospective` は下の「経路ごとの適用」）に従う。

## 経路ごとの適用

- **`/create-issue`**: 上の節をすべて使う。雛形は SKILL.md 手順 6
- **`/out-of-scope-issue`**: 発見を手早く記録する経路なので、`## 概要`・`## 目的と期待効果`・`## 発見元`・`## 受け入れ条件` の 4 節にする。`## 関連` は置かず、台帳の番号などの管理情報は `## 発見元` へ書く。雛形は同スキルの references/filing.md §3.3
- **`/retrospective`**: 提案の欄を次の節へ写す
  - 実測 → `## 背景` には、何が起きて何を失ったかの要約だけを 1〜3 行で書く。台帳の番号・Count・セッションごとの詳しい経緯は `## 関連` へ回す（目的と期待効果より前に、管理番号の並んだ経緯を置かない）
  - 期待効果 → `## 目的と期待効果`、提案（代替案を含む）→ `## やること`、既存確認 → `## 関連`
  - ストーリーは、実測と期待効果から 1 文で書く（種別に応じてユーザーストーリーかジョブストーリー）
  - 受け入れ条件は、提案から検証できる形で書く。提案だけでは材料が足りなければ、推測で埋めず、受け入れ条件の節に「着手時に決める」と書いて、足りない材料を 1 行添える
  - `/create-issue` が使えない fallback（`/retrospective` の references/filing.md「承認と起票」手順 3）で起票するときは、`## 参照文書` と `## 工数見積もり（KPI 計測）` を省いてよい（着手時に追記する）
- **リポジトリに `.github/ISSUE_TEMPLATE/` がある場合**（`/create-issue` と、それを通して起票する `/retrospective` に当てる。`/out-of-scope-issue` はテンプレートがあっても上の 4 節のまま起票する）: テンプレートにしかない節は残す（`/create-issue` の references/filing.md「ISSUE_TEMPLATE 節の pre-flight」。埋められない節を「なし」と書いて残すのは同節の規定で、上の「行を足さない」とは別の話）。同じ役割の節が両方にあるときは、テンプレートの見出しにそろえて 1 つにし、同じことを 2 か所に書かない

| 本書の節 | テンプレートで同じ役割を持つことが多い見出し |
| -------- | ------------------------------------------ |
| `## 背景` | `## 再現手順`・`## 期待される動作`・`## 実際の動作`（bug） |
| `## やること` | `## 変更内容`・`## 変更方針`・`## 対象ファイル`、`## スコープ外`（やらないこと） |
| `## 参照文書` | `## 参照ドキュメント` |
| `## 関連` | `## 関連Issue` |
